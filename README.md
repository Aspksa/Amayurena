# Amayurena

Amayurena — локальная персональная веб-панель с **каталогом ИИ-агентов** и **индивидуальным рабочим пространством** каждого агента.

## Быстрый запуск на Windows

1. Установите **Node.js 20+** (если ещё не установлен). Сборка проекта и npm-зависимости не требуются.
2. Скачайте проект (Code → Download ZIP) и распакуйте на любой диск или внешний SSD.
3. Дважды нажмите **`Amayurena.bat`**. Права администратора не нужны. Локальный сервер займёт свободный порт и откроет веб-страницу.
4. Создайте агента в меню **«Агенты»**, откройте его карточку кнопкой **«Открыть»**.
5. Чтобы получить ответы от Cloud.ru, задайте параметры подключения (инструкция ниже) и перезапустите `Amayurena.bat`.

Без ключа Cloud.ru каталог и **локальные ручные инструменты** работают, а запросы модели отключены с понятным предупреждением. При прямом открытии `index.html` каталог по-прежнему работает без Node.js, однако рабочее пространство **не сможет вызывать API** без запуска сервера.

## «Знания» — собственная база с нуля

Amayurena не требует готовых файлов или переноса данных из других программ. При первом запуске база **пустая**. Весь материал создаётся в самой Amayurena, вручную. Шаблоны только подставляют начальную структуру, не выдумывают факты.

1. Запустите `Amayurena.bat` (Node.js 20+), откройте раздел **«Знания»**.
2. Нажмите **«＋ Первая заметка»** или **«＋ Заметка»**. Введите название, выберите папку и встроенный шаблон: чистый лист, идея, проект, задача либо исследование. Предпросмотр покажет, что будет создано.
3. Нажмите **«Создать заметку»**, затем редактируйте её текст. Автосохранение работает после паузы; доступно сочетание Ctrl+S.
4. При необходимости создайте собственные папки кнопкой **«＋ Папка»**. Для связи существующих заметок используйте `[[Название]]` или `[[Папка/Название]]`.
5. Откройте **«Граф»**, **«Canvas»** или **«Bases»**, чтобы видеть связи, составлять визуальные доски и изучать свойства записей.

Создание заметки использует специальный API, который не перезаписывает существующий файл: совпадение имени возвращает ошибку, а текст старой заметки сохраняется. Система не заполняет базу автоматическими примерными записями и не обращается к Cloud.ru при создании и просмотре знаний.

### Хранение и функции

- Обычные Markdown-файлы заметок находятся в `data/knowledge/`, доски — в `data/canvases/`, предыдущие редакции заметок — в `data/knowledge-history/`. Вся папка `data/` исключена из Git.
- Редактор содержит безопасный предпросмотр заголовков, текста, выделения, таблиц, цитат, блоков кода, списков задач и ссылок; произвольный HTML не исполняется.
- Граф показывает первые 80 заметок и связи между ними; справа есть обратные ссылки и история выбранной заметки.
- Canvas поддерживает создание собственных досок, текстовых карточек, карточек заметок, перетаскивание и связи. На доску допускается до 60 карточек и 120 связей.
- Bases автоматически формирует таблицу из свойств в верхней части заметок; доступны поиск, сортировка, фильтр и открытие записи. Редактирование ячеек прямо в таблице пока не реализовано.
- Перед изменением или удалением заметки прежнее содержимое записывается в историю (до 20 редакций), доступно восстановление. Дополнительно регулярно копируйте `data/` на отдельный носитель.

Пример собственных свойств, которые отображаются в Bases:

```markdown
---
type: project
status: Планируется
priority: Средний
---
# Мой проект

[[Идеи]]
```

**Что осталось на будущие этапы:** формулы и вычисляемые поля Bases, бесконечное поле Canvas, внешние резервные копии, локальная смысловая индексация и контролируемая интеграция с агентами. Импорт файлов из других программ не входит в планы разработки этого раздела.

## Пакет №10 — надёжность знаний

Новые функции доступны в разделе **«Знания»**; запускайте программу через `Amayurena.bat`. Все операции выполняются локально, без Cloud.ru.

- **Автосохранение:** после паузы ввода изменения записываются на диск. Сервер проверяет SHA-256 исходной версии и возвращает `409`, если файл изменён другим окном: чужой текст не перезаписывается. При сбое несохранённый текст остаётся в редакторе, а черновик сохраняется в `sessionStorage` до закрытия браузерной сессии. Открытие заметки предлагает восстановить найденный черновик. Сохраняйте вручную перед закрытием устройства; sessionStorage не заменяет резервную копию.
- **Поиск:** поле слева выполняет полнотекстовый поиск по всем заметкам Markdown на локальном диске, не только по заголовкам и фрагментам. Результаты содержат контекст и позволяют открыть запись.
- **Корзина:** удаление переносит содержимое заметки в локальную корзину `data/trash/` (без автоматической очистки); восстановление выполняется без перезаписи существующей записи с тем же путём.
- **Переименование и перемещение:** кнопка рядом с открытой заметкой и действия на заголовках папок. Совпадающие пути не перезаписываются. При переносе обновляются однозначные полные wiki-пути, ссылки Canvas и расположение истории заметки; короткие ссылки и нестандартные ссылки рекомендуется проверить вручную.
- **Резервные копии:** кнопка вверху раздела. Полный снимок всех заметок, истории, Canvas-досок и корзины сохраняется в `data/backups/` (папки с контрольными суммами SHA-256 и манифестом). Можно создать и восстановить снимок. Восстановление заменяет текущие данные этих четырёх разделов, поэтому перед ним обязательно сделайте новую копию. Объём одного снимка ограничен 256 МиБ. Снимок остаётся на том же диске: для защиты от поломки накопителя отдельно копируйте папку `data/` на другой носитель.
- **Ограничения:** невозможно надёжно сохранить запись при внезапном выключении питания во время файловой операции; при конфликте редактирования пользователь должен вручную согласовать изменения. Не сохраняйте личные заметки в публичный GitHub-репозиторий. Код автоматических проверок не заменяет визуальное тестирование на Windows.

## Пакет №11 — профессиональный редактор знаний

Редактор работает в существующем разделе **«Знания»** и не требует облачных сервисов.

- **Дерево папок:** вложенные папки с раскрытием и сворачиванием, рядом с каждой папкой доступен перенос и переименование; раскрытые разделы сохраняются в браузере. Папка может быть пустой.
- **Вкладки:** открывайте до 12 заметок, переключайтесь между ними и закрывайте независимо от удаления самих файлов. Вкладки и навигация хранят только пути заметок в локальном хранилище браузера; содержимое заметок хранится на диске.
- **Безопасная смена вкладок:** переходы выполняются последовательно. Перед переключением и закрытием активной вкладки завершается автосохранение с проверкой SHA; при ошибке или конфликте переход отменяется, а редактор и локальный черновик сохраняются. Для перехода используйте клик по вкладке или Ctrl+Tab.
- **Спасение конфликтного черновика:** кнопка «Сохранить копию» записывает текст в новый Markdown-файл через create-only API. Исходная заметка другого окна не перезаписывается. Выбирайте новое уникальное имя.
- **Избранное и закрепление:** звёздочка у заметки и кнопки у заголовка. Избранное показывается в отдельном списке, закреплённые вкладки поднимаются в начало полосы.
- **Быстрые переходы:** недавние записи, интерактивный путь в заголовке, Ctrl+K для фокусировки поиска. В поиске сохраняется полнотекстовая проверка из пакета №10.
- **Форматирование:** панель для заголовков, жирного и курсивного текста, кода, маркированных списков, задач, цитат, обычных и внутренних ссылок. Выделенный текст сохраняется внутри вставленных конструкций. Горячие клавиши Ctrl+B, Ctrl+I, Ctrl+S.
- **Адаптация:** дерево, панель редактирования и горизонтальная полоска вкладок приспосабливаются к узким экранам, включая мобильные браузеры.

Важное ограничение: автоматические тесты проверяют модель вкладок, форматирование и сохранение данных; для окончательной проверки удобства нужен ручной просмотр в браузере Windows. Вкладки не являются одновременными независимыми редакторами: перед показом другого файла текущий должен быть успешно сохранён.

## Пакет №12 — собственные редактируемые Bases

В разделе «Знания» откройте **Bases**. Таблицы строятся из свойств заметок, созданных внутри Amayurena. Импорт файлов не нужен.

- **Редактирование:** нажмите значение свойства, введите новое значение и нажмите ✓ или Enter. Для флажков сохранение происходит при переключении. Escape или × отменяет редактирование. Изменения записываются в Markdown-заметку, а предыдущая версия сохраняется в истории.
- **Типы полей:** текст, число, дата (ГГГГ-ММ-ДД), флажок, выбор, метки. Добавляйте новое поле над таблицей; тип имеющегося поля изменяется кнопкой заголовка. Старые значения при смене типа автоматически не преобразуются.
- **Представления:** таблица и карточки, сортировка по выбранному полю и направлению, фильтр по значению, группировка по одному полю, текстовый поиск. До 30 сохранённых видов с именами; удаление вида не удаляет заметок.
- **Хранение:** значения находятся в data/knowledge/, типы и сохранённые виды — в data/knowledge-bases/views.json. Полный резервный снимок теперь включает пятый раздел «bases». Старые четырёхраздельные копии по-прежнему поддерживаются.
- **Защита:** сервер проверяет SHA-256 текущей заметки и версии настроек, предотвращая конфликтующие записи. Ввод проверяется; произвольные HTML и скрипты из ячеек не исполняются.
- **Ограничения:** пока нет формул, вычисляемых полей, сложных составных фильтров или коллективного редактирования. За раз отображаются первые 250 строк; уточняйте фильтр. Для старых значений может потребоваться ручная корректировка типа.

## Пакет №13 — продвинутый Canvas

В разделе **«Знания» → «Canvas»** создавайте и редактируйте собственные доски с нуля, без импорта файлов.

- **Масштаб:** кнопки +/−, возврат к 100%, «Вписать», Ctrl + колесо мыши; масштаб ограничен 35–200% и сохраняется локально для каждой доски.
- **Мини-карта:** показывает группы, карточки и видимую область. Нажмите на точку карты для перехода к ней.
- **Группы:** кнопка «＋ Группа» создаёт цветную область; карточка с командой «В группу» назначается выбранной группе. Группу можно передвинуть вместе с относящимися к ней карточками, переименовать или удалить без удаления самих карточек. До 20 групп на доску.
- **Автоматическая раскладка:** кнопка «Упорядочить» после подтверждения расставляет карточки и группы детерминированно, сохраняя текст, ссылки и принадлежность группам.
- **Навигация:** средняя кнопка мыши перемещает рабочую область; стрелки/полосы прокрутки доступны как обычно. На рабочей области клавиши Home (к началу), F (вписать), +/− (масштаб).
- **Надёжное сохранение:** каждая запись доски проверяет SHA-256 предыдущей версии файла. При конфликте с изменениями другого окна сохранение отклоняется; доска остаётся открытой. Перед переключением, созданием или удалением доски завершается очередь сохранения. При ошибке переключение отменяется.
- **Совместимость:** старые локальные Canvas-файлы без групп открываются автоматически с пустым списком групп. Markdown-заметки и Bases не меняются. Резервные копии уже включают файлы Canvas.

Ограничения: не более 60 карточек, 120 связей и 20 групп на доску. Рабочее поле остаётся ограниченным 3500×2600 логическими единицами — бесконечного полотна пока нет. Автоматические тесты запускаются в GitHub Actions; ручная визуальная проверка на Windows остаётся отдельным шагом.

## Пакет №14 — Живая карта знаний

Откройте раздел **«Знания» → «Живая карта»**. Анализ выполняется локальным Node.js без Cloud.ru, API-ключей и отправки материалов в облако.

Карта объединяет ссылки `[[Имя заметки]]`, связи карточек заметок на досках Canvas, метки и названия свойств Bases. У каждого узла есть путь к оригинальному Markdown-файлу, дата обновления, история версий и список досок, где он используется. Для каждой подтверждённой связи показан её источник: исходная строка wiki-ссылки или имя Canvas-доски и идентификаторы соединённых карточек.

Неявное сходство вычисляется **локальной эвристикой** пересечения значимых слов и меток; это не нейросетевая модель и не доказательство истинности факта. Такие связи рисуются пунктиром и не изменяют заметок автоматически. Для каждого предложения можно увидеть общие слова и метки. Кнопка «Подтвердить связь» только после отдельного подтверждения пользователя добавляет обычную wiki-ссылку в исходную заметку, предварительно проверяет версию обеих заметок и сохраняет исходный текст в истории. При конфликте изменений операция отклоняется.

В «Нужно проверить» отдельно выводятся отсутствующие wiki-ссылки и различающиеся значения одинаковых полей у похожих записей. Различие свойств — **не подтверждённое противоречие**. Для проверки авторства, времени и доказательной силы источника по-прежнему нужен самостоятельный анализ документов.

Ограничения: анализируются первые 180 заметок в устойчивом алфавитном порядке, на схеме отображается до 60 узлов, список выдаёт до 60 предложений. На больших базах карты и подсказки неполны — этот факт отображается в интерфейсе. Никакого бесконтрольного самообучения или автоматического изменения знаний нет. Режим не создаёт дополнительные заметки, не импортирует внешние файлы и не добавляет тяжёлых зависимостей.

## Новое: Canvas, Bases и большая карта знаний

- **Canvas 2.0, первый этап:** шаблоны пустой доски, карты идей и трёх этапов; отмена и повтор до 40 последних состояний, выделение нескольких карточек с Ctrl/Command, «Выделить всё», копирование карточек со связями, привязка к сетке 25 единиц. Карточки за пределами видимой области временно не отрисовываются; данные доски и её автосохранение при этом не меняются.
- **Bases 2.0, первый этап:** вычисляемые числовые поля с безопасной арифметикой (+, −, ×, ÷, скобки, названия числовых свойств), без eval и запуска произвольного кода. Сохранённые формулы не изменяют исходный Markdown. Добавлены итоги суммы/среднего для показанных строк, расширенные операторы фильтра и вид календаря как список карточек, сгруппированных по датам. Полноценная сетка месяца и связанные записи ещё не реализованы.
- **Живая карта 2.0, первый этап:** обзор всего хранилища через папочные кластеры, поиск и страницы до 120 узлов; каждая страница получает реальные wiki-связи внутри неё. В инспекторе можно видеть восстановленную из истории заметки хронологию изменения wiki-ссылок. Старый анализ сходства остаётся ограниченным первыми 180 заметками; представление всех узлов одновременно и полная история Canvas ещё не реализованы.

Все изменения локальны, не используют Cloud.ru и не вводят память агентов. Перед установкой следующего обновления рекомендуется сохранить отдельную резервную копию папки data/.

## Пакет №18 — проверяемое обновление из GitHub Releases

Система рассчитана на локальный запуск через `Amayurena.bat` на Windows с Node.js 20+ и не требует прав администратора.

**Проверка:** при открытии веб-версии автоматически проверяется последний опубликованный стабильный релиз репозитория Aspksa/Amayurena. Кнопка «Проверить обновления» повторяет запрос. Если релизов нет, приложение сообщает об этом, а не выдумывает доступную версию.

**Установка:** после подтверждения в интерфейсе локальный сервер запускает отдельный установщик, завершает свою работу, а установщик скачивает файл `Amayurena-update.zip` только с официальной страницы релиза, сверяет SHA-256 с атрибутом digest GitHub, проверяет ZIP на неправильные пути, ссылки, подозрительные имена, переполнение и повреждения. Без digest установка отклоняется. Перед заменой выполняется полный локальный снимок папки знаний, истории Canvas, Bases и корзины через систему пакета №10. Код приложения копируется с отдельным резервированием каждого заменённого файла и журналом отката. Папки `data/`, `.env` и `.updates/` никогда не распаковываются поверх пользовательских файлов. При ошибке выполняется откат; если процесс прерван, BAT попытается восстановить файлы при следующем запуске.

После успешной установки запускается `Amayurena.bat`. Итог диагностики можно увидеть в `.updates/updater.log`. В качестве резервного варианта после закрытия основного окна доступен `Amayurena-Update.bat` (проверка, скачивание, установка и перезапуск).

**Выпуск обновлений:** первый релиз создаётся GitHub Actions при публикации тега `vX.Y.Z`, совпадающего с `project-version.json`. Workflow сначала проверяет синтаксис и тесты и только затем формирует переносимый ZIP и публикует релиз. Пока тега и официального релиза нет, установщик ничего не меняет. Не запускайте обновление с неподтверждённых сторонних архивов.

Ограничения: Windows-инсталляция и перезапуск требуют отдельного практического испытания на Windows; обычный Ubuntu CI проверяет алгоритмы и интеграцию, но не заменяет этого испытания. Рекомендуется дополнительно хранить копию папки `data/` на другом накопителе.

## Вложения заметок — редактор 2.0

В разделе «Знания», открыв заметку, нажмите **«Прикрепить файл»**. Разрешены изображения PNG/JPG/WEBP, PDF, TXT, Markdown, CSV, XLS/XLSX и DOCX, максимум 5 МиБ на один файл и 800 файлов на хранилище. Никакие вложения не запускаются и не отображаются как исполняемая HTML-разметка: скачивание принудительно отдаёт `application/octet-stream`.

Все файлы лежат локально в `data/knowledge-attachments/` (метаданные и бинарные данные с SHA-256), без Cloud.ru и без внешнего импорта базы знаний. Они связаны с конкретной заметкой. Переименование и перенос заметки/папки обновляют связи; удаление в корзину скрывает вложения, а восстановление возвращает доступ. Снимки резервной копии теперь включают шестой раздел `attachments`; старые четырёх- и пятираздельные снимки остаются совместимы с восстановлением. При повреждении файла проверка контрольной суммы блокирует скачивание.

Это прикрепление локальных файлов, а не полноценная индексация вложений или извлечение из них знаний. Данные больших вложений увеличивают объём копий; предел полного снимка по-прежнему 256 МиБ. Для защиты от поломки внешнего SSD сохраните папку `data/` на другом носителе.

## Bases 2.0 — календарь месяца и связанные заметки

В Bases доступны новый тип поля **«Связь с заметкой»** и календарное представление настоящего месяца. Связь — это путь к уже существующему Markdown-файлу. Значение сохраняется в frontmatter исходной заметки как wiki-ссылка. Отсутствующие пути и попытки обхода каталогов отклоняются, прежняя версия заметки остаётся в истории. В таблице рядом со связью есть действие «Открыть связь». Перенос заметок использует существующее исправление wiki-ссылок пакета №10.

В представлении «Календарь (месяц)» выберите поле типа «Дата» и нужный месяц. Появится сетка понедельник—воскресенье, переходы между месяцами, записи по дням; нажатие записи открывает заметку. Без даты заметка на сетке не отображается, но в данных Bases остаётся. Ручная синхронизация с внешним календарём не выполняется.

Виды, поля и формулы сохраняются локально, никакие фоновые процессы или память ИИ-агентов не добавляются.

## Журнал выполнения ИИ-агентов

В карточке агента доступны **включение и остановка ручных запросов**. В рабочем пространстве показан локальный журнал до 100 последних событий: включение и остановка агента, выполненные диалоги и задачи, ошибки, отмена ожидания, использование разрешённых инструментов. По доступным данным показываются модель, длительность и токены.

Журнал не сохраняет текст сообщений, содержимое файлов, ключи Cloud.ru или ответы инструментов. Данные остаются в браузерном localStorage конкретного агента. История сообщений и журнал — разные хранилища внутри одного локального объекта; автоматических фоновых задач и долгосрочной памяти ИИ-агентов нет. Удаление браузерных данных удалит и этот журнал.

## Подключение Cloud.ru

Используется публичный **ML Inference** endpoint с OpenAI-совместимым `/v1/chat/completions`. Его URL можно найти в Cloud.ru → AI Factory → ML Inference → Публичные эндпоинты. Модель для публичного endpoint по умолчанию — `endpoint-selected`.

Установите переменные окружения **в Windows CMD для текущей сессии**:

```bat
set "AMAYURENA_API_BASE_URL=https://YOUR-ENDPOINT-shared.modelrun.inference.cloud.ru/v1"
set "AMAYURENA_API_KEY=YOUR_PRIVATE_KEY"
set "AMAYURENA_MODEL=endpoint-selected"
Amayurena.bat
```

Запускать команды нужно из папки с проектом. Вместо этого можно задать переменные окружения Windows для своей учётной записи. **Не добавляйте ключи в файлы проекта, инструкции агентов, git или публичные репозитории.** API-ключ используется **только сервером**, не передаётся браузеру. Он не сохраняется приложением на диск.

При использовании отдельного названия модели укажите его в карточке агента. Пустое поле берёт `AMAYURENA_MODEL` (или `endpoint-selected`). Параметры зависят от эндпоинта; некоторые модели не умеют вызывать инструменты. В этом случае снимите галочки инструментов и повторите запрос.

**Стоимость:** Cloud.ru может тарифицировать запросы согласно вашему тарифу. Amayurena не может подтвердить бесплатность выбранной модели и не отправляет запросы автоматически — только после нажатия **«Отправить»** или **«Выполнить задачу»**. На один запрос установлено ограничение длины, максимального вывода и числа вызовов инструментов.

- **Правый клик** — контекстное меню «Выбрать аватар», «Эффекты», «Анимация», «Скрыть», «Сбросить положение».
- Перетаскивание мышью или касанием; положение и размер сохраняются в браузере.

- Возможность заменить позы собственными PNG/JPEG/WebP прямо в настройках: один файл заменяет выбранную позу, несколько файлов — первые позиции. Изображения уменьшаются и сохраняются только в браузере.

### Как добавить исходные изображения

**В проект теперь входит встроенный набор `assets/avatars/sprite.avif`** с изображениями всех 10 поз. Он сделан из присланных пользователем иллюстраций: 8 уникальных изображений и 2 повторения. Ресурс оптимизирован для интерфейса (192×192 пикселя на позу) и загружается автоматически, даже если ZIP не установлен. На актуальных браузерах с поддержкой AVIF выбор поз работает сразу после скачивания GitHub-репозитория.

**Полноразмерные исходники 1024×1024** по-прежнему поставляются отдельно архивом `Amayurena_10_avatars.zip` из чата. Установка ZIP заменяет встроенные превью более качественными WebP из `assets/avatars/pose-XX.webp`. При отсутствии поддержки AVIF сайт покажет резервную SVG-иллюстрацию.

### Установка десяти поз одним нажатием

1. Скачайте отдельный архив `Amayurena_10_avatars.zip` с оригинальными изображениями из чата.
2. Запустите сайт через `Amayurena.bat` (локальный сервер Node.js, без прав администратора).
3. Щёлкните правой кнопкой мыши по аватару → **«Выбрать аватар»**.
4. Нажмите **«Установить все 10 поз из ZIP»**, выберите архив и подтвердите замену.

Сервер проверит имена всех файлов, размер, контрольные суммы и формат WebP, затем установит их в `assets/avatars/`. Оригинальные изображения сохраняются **в папке проекта**, а не только в браузере, поэтому сохраняются после очистки кэша. Механизм умеет заменить ранее установленные позы с попыткой отката при сбое записи.

Альтернативно архив можно распаковать вручную в корневую папку проекта. После этого должны существовать:
```
assets/avatars/pose-01.webp
...
assets/avatars/pose-10.webp
```
Обновите страницу и выберите любую из десяти поз.

**Ограничение:** в GitHub включён оптимизированный бинарный AVIF-набор, но не полноразмерные 1024×1024 WebP. ZIP нужен только для максимального качества изображения; он не нужен для работы меню и выбора поз. Действие в приложении не публикует файлы в GitHub и не требует GitHub-токена.

Встроенная графика не содержит реального покадрового движения: анимации по-прежнему CSS.\n\nАльтернативный путь: откройте настройки аватара → «Загрузить свои изображения» и выберите 10 файлов из компьютера. Они сохранятся в браузере в сжатом виде и не требуют изменения репозитория. Для работы без пользовательских картинок существует локальная SVG-заглушка; отсутствие изображений не ломает интерфейс.

**Важно:** это анимация статичного изображения с помощью CSS, а не настоящая покадровая анимация персонажа (например, отдельная мимика глаз). Для неё понадобятся дополнительные кадры, Live2D или 2D-риггинг.

### Публикация локальных аватаров в GitHub через PR

После установки ZIP можно **опубликовать все десять WebP в публичный репозиторий** прямо из сайта. Это отдельное действие, оно **не запускается автоматически** и не затрагивает другую часть кода.

1. Создайте GitHub fine-grained Personal Access Token для репозитория `Aspksa/Amayurena` с правами **Contents: Read and write**, **Pull requests: Read and write**. Не публикуйте токен.
2. Откройте CMD в папке Amayurena и задайте токен **только для этой сессии**:
   ```bat
   set "AMAYURENA_GITHUB_TOKEN=ВАШ_GITHUB_TOKEN"
   Amayurena.bat
   ```
   Не записывайте ключ в `README`, `.bat`, исходный код или репозиторий.
3. Правый клик по аватару → «Выбрать аватар» → убедитесь, что в блоке публикации написано «Установлено: 10 / 10».
4. Нажмите **«Создать PR с аватарами»** и подтвердите, что изображения станут публичными.
5. Откройте созданный Pull Request и проверьте изображения и GitHub Actions. После проверки слейте PR в `main` обычным способом.

Сервис публикует **только** `assets/avatars/pose-01.webp` … `pose-10.webp`, не принимает произвольные пути, проверяет реальный формат WebP и ограничивает размеры. Токен используется локальным сервером; браузер получает только признак настройки и ссылку на PR. Существующие файлы в `main` не меняются до слияния PR.

В архиве из этой переписки десять файлов, но есть одинаковые пары поз: `pose-01`/`pose-06` и `pose-05`/`pose-07`. Таким образом, в нём **8 уникальных изображений**. Их можно заменить через сайт до публикации. Эта особенность не считается ошибкой ZIP.

**Ограничение:** пока пользователь не запустил локальную публикацию с правами GitHub и не слил созданный PR, сами изображения в GitHub не появятся.

## Меню «Агенты»

- Создание, редактирование, удаление, фильтр и поиск карточек.
- Поля агента: имя, роль, описание, инструкции, модель, список разрешённых инструментов.
- До 500 конфигураций.
- Экспорт/импорт конфигураций в JSON с проверкой и подтверждением замены.
- Кнопка **«Открыть»** ведёт в пространство агента:
  - **Диалог** — отправка сообщений модели и локальная история.
  - **Задачи** — ручной запуск однократного запроса и журнал ответов.
  - **Инструменты** — три безопасные локальные функции (счётчик слов/строк, арифметика, время UTC).
- Модель может использовать разрешённые инструменты при поддержке функции tool calling. Возможность тестировать инструменты вручную остаётся и без облачной модели.
- История каждого агента хранится в `localStorage` браузера, отдельном для каждого агента. Экспорт JSON каталога **не содержит историю диалогов**. История и каталог не синхронизируются между компьютерами.

### Чего пока нет

Автономной работы в фоне, планировщика, доступа к файлам/интернету от имени агента, связи между агентами, долгосрочной семантической памяти и самостоятельного обучения **пока нет**. Одно нажатие «Выполнить задачу» — один ограниченный запрос модели с разрешёнными локальными вычислениями. Никакой агент не получает права запускать команды Windows или изменять файлы.

## Безопасность и данные

- HTTP-сервер слушает **только 127.0.0.1** и по умолчанию выбирает свободный порт. Нет доступа из локальной сети.
- Сервер использует allowlist статических файлов, заголовки защиты, проверку Host/Origin, ограничения размера запросов и число одновременных обращений к модели.
- URL Cloud.ru задаётся только в окружении сервера; из браузера изменить его нельзя. Поддерживаются только HTTPS-адреса поддоменов `cloud.ru`.
- Текст бесед и системные инструкции отправляются в Cloud.ru при использовании модели. Не передавайте секреты или личную информацию без необходимости.
- История в браузере не зашифрована. При очистке данных браузера она может исчезнуть. При прямом запуске `file://` особенности `localStorage` зависят от браузера.
- Ключ не включён в ответ API и не хранится в истории.

## Разработка и проверки

Зависимостей из npm нет; требуется Node.js 20+ для серверных вызовов и тестов.

```sh
node --check agents-core.js
node --check app.js
node --check workspace.js
node --check server.js
node --check server-core.js
node --test tests/*.test.cjs
```

`node server.js` запускает локальный сервер. По умолчанию используется свободный порт; при необходимости задайте `AMAYURENA_PORT`.

GitHub Actions выполняет проверки синтаксиса и unit/integration tests при PR и push в `main`.
